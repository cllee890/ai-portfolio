# 工单分类与回复草稿流水线

## 目标
把售前、售后、投诉等多渠道留言自动分类、判定优先级，并生成回复草稿。**所有草稿固定为 `pending_review`，程序不会自动发送**；投诉、拒付、合作类工单强制标记为需人工介入。

## 处理流程
```
工单 → 脱敏（手机号、邮箱） → 关键词规则分类 → 优先级判定 → 人工介入判定 → 回复草稿（模板 + 订单号）
```

- **分类规则**按顺序匹配，先命中的优先（如同时含"冒烟"和"退款"，归为质量投诉）。
- **优先级**：含"冒烟、起火、受伤、拒付、起诉、投诉"等词或属于拒付纠纷为高；退款、物流、质量类为中；其余为低。
- **脱敏**：手机号保留前三后四位，邮箱只保留域名。脱敏后的文本写入报告，原文不落盘。

## 目录结构
```
ticket-triage/
├── triage.py          # 分类与草稿生成（纯标准库，离线规则）
├── test_triage.py     # 16 个单元测试
├── data/tickets.jsonl # 8 条示例工单
└── reports/
    ├── triage.jsonl   # 每条工单的结构化结果
    └── report.md      # 分类汇总与明细
```

## 运行说明
```bash
cd workflows/ticket-triage
python triage.py                           # 使用示例数据
python triage.py --input 工单.jsonl --out 输出目录
python -m unittest test_triage -v
```
输入每行一条 JSON：`{"id", "channel", "subject", "body"}`。

## 注意事项
- 关键词规则只适合演示与兜底。生产环境可在此基础上替换为分类模型，但"投诉类必须人工处理"的规则应保留。
- 回复模板中的承诺（如"1-3 个工作日"）需与真实政策一致，上线前由客服负责人确认。
- 不得把草稿直接发送给买家，发送前必须人工审核。
