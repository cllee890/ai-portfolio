# 多节点串联工作流：选品 → 文案 → 质检 → 发布

## 目标
将"竞品数据抓取 → 标题生成 → 合规检查 → 人工确认 → 发布 API"串联为一条可复用流水线。

## 节点设计
| 节点 | 类型 | 输入 | 输出 | 失败处理 |
|---|---|---|---|---|
| N1 数据输入 | 表单/Excel | 商品属性 | JSON | 字段缺失则终止 |
| N2 竞品参考 | HTTP 工具 | 关键词 | 竞品标题列表 | 超时重试 2 次 |
| N3 文案生成 | LLM（模板 prompts/industry-prompt-templates.md） | N1+N2 | 标题/卖点 JSON | 解析失败回退重试 |
| N4 合规检查 | LLM + 规则词表 | N3 | 风险等级 | 高风险进入人工 |
| N5 人工确认 | 审批节点 | N4 | 通过/修改 | 超时提醒 |
| N6 发布 | HTTP API | N5 | 商品ID | 幂等键防重复 |

## 关键实现要点
- 每个节点输出统一 JSON Schema，便于替换模型。
- 变量与密钥放入环境变量或平台凭证库，不写入流程文件。
- 节点日志记录耗时、token 数与错误码，便于排查。

## 运行说明
本目录是**流程设计示例**，不含可独立执行的程序。落地时按以下步骤在工作流平台或自建调度器中配置：

1. 按上表创建 N1–N6 六个节点，并为每个节点设置输入/输出 JSON Schema。
2. N2 配置竞品检索接口地址与密钥（使用环境变量或平台凭证库）。
3. N3 引用 `prompts/industry-prompt-templates.md` 中的文案模板，并配置解析失败的重试次数。
4. N4 配置规则词表；风险等级为"高"时进入 N5 人工确认。
5. N6 配置发布接口，并传入由商品信息生成的幂等键。
6. 为每次运行记录各节点耗时、token 数与错误码。

## 示例输入输出
以下为一次成功运行时各节点的示意数据（字段仅为示例，实际以 Schema 为准）。

**N1 数据输入 → 输出**
```json
{"sku": "KB-1024", "category": "键盘", "price": 129.0, "attributes": ["无线", "静音", "蓝牙5.0"]}
```

**N2 竞品参考 → 输出**
```json
{"keyword": "无线静音键盘", "competitor_titles": ["无线静音键盘 蓝牙5.0 办公家用", "静音无线键盘 便携 双模"]}
```

**N3 文案生成 → 输出**
```json
{"titles": ["无线静音键盘 蓝牙5.0 办公家用"], "selling_points": ["静音设计，适合夜间办公", "蓝牙5.0 稳定连接"]}
```

**N4 合规检查 → 输出**
```json
{"risk_level": "low", "hits": []}
```

**N5 人工确认 → 输出**
```json
{"decision": "approved", "reviewer": "运营A"}
```

**N6 发布 → 输出**
```json
{"status": "published", "product_id": "P20261121-0007", "idempotency_key": "KB-1024-v1"}
```

**异常示例**：N4 返回 `{"risk_level": "high", "hits": ["绝对化用语：最好"]}` 时，流程停在 N5 等待人工修改，不会直接进入 N6。
