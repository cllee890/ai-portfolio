# 输出格式规范（Output Format Specification）

用于统一大模型输出结构，便于下游程序解析与业务人员阅读。

## 一、通用规则
1. **结构先行**：先输出结论，再输出依据与细节。
2. **可解析**：需要程序处理时强制输出 JSON，并给出字段类型与示例。
3. **明确缺失**：信息不足时输出 `null` 或"【待补充】"，禁止臆造。
4. **长度约束**：每个字段给出字数上限。
5. **语言一致**：输出语言与用户输入语言保持一致，除非另有指定。

## 二、常用格式模板

### 1. JSON（程序调用）
```json
{
  "summary": "string, ≤50字",
  "items": [
    {"name": "string", "priority": "high|medium|low", "reason": "string"}
  ],
  "confidence": "number, 0-1"
}
```

### 2. Markdown 表格（人工阅读）
| 字段 | 说明 | 示例 |
|---|---|---|
| 问题 | 现象描述 | 落地页加载超过 4 秒 |

### 3. 分段报告
```
## 结论
## 依据
## 行动建议（编号列表，每条含负责人与时间）
```

## 三、校验清单（上线前必查）
- [ ] 输出能被 JSON 解析器通过（若要求 JSON）
- [ ] 必填字段齐全，枚举值在允许范围内
- [ ] 无多余解释文字包裹在 JSON 外
- [ ] 长度与语言符合约束

## 四、优化前后对比示例
- **优化前**：要求"列出几个优点"，输出为自由段落，难以解析。
- **优化后**：指定 JSON 数组 `[{"point": "", "evidence": ""}]`，解析成功率显著提高（以内部测试集为准，可替换为实测数据）。
